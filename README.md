# 加油站班次核销台

一个班次汇总**油枪泵码读数、现金、电子支付、银行回执**，解决「只记总额、设备读数与到账回执对不上只能翻纸单」的问题。
技术栈：Vue 3 + Vite + TypeScript + Pinia。数据存 localStorage（模拟服务端状态 + 多窗口并发），核心核销逻辑为纯函数并配单测。

## 启动

```bash
npm install
npm run dev       # 本地开发
npm run test      # 领域规则 + store 集成测试（vitest）
npm run build     # vue-tsc 类型检查 + 产物构建
```

## 业务规则

- **按 终端号 + 回执号 合并**：电子支付流水与银行回执据此配对。
  - 已匹配电子支付 → 计入**当班收入**；
  - 有支付流水、无银行回执 → **待核（挂起）**，保留差异，**不计收入**；
  - 有银行回执、无支付流水 → **挂账待核**，保留差异，**不计收入**；
  - 因此未匹配回执不会拉高当班收入。
- **断网留草稿**：离线保存只进 outbox（不改生效结果），网络恢复后按时间顺序重放合并。
- **确认即冻结**：确认班次时固化油枪读数、现金、支付流水、已匹配回执与当时口径快照，之后永不改写。
- **只追加冲正、重算未确认部分**：
  - *晚到回执* → 对已确认班追加 `late_receipt`，把原挂起金额补入收入并冲减待核差异；
  - *跨班退款* → 追加 `cross_shift_refund`；退的是已计收入则冲收入，退的是挂起流水则只冲待核；
  - *泵码更新* → 追加 `pump_adjust`，只改泵码油款口径与泵码↔收款差异，不动现金/电子收入，原终码保留；
  - 未确认班次发生退款/更新则直接在当前数据上重算，不留冲正。
- **乐观锁并发**：每个班次带 `version` 与版本归属（`versionOwner`）。两个窗口基于同一旧版本保存，
  后到的一方判**版本冲突**，操作转成**冲突草稿**保留，绝不覆盖已生效结果；可载入草稿在最新结果上人工合并。
- **可续处理**：草稿、冲突、网络状态、当前选中班次都持久化，关掉页面/浏览器再打开可接着处理。

## 页面

- 左侧：班次列表（状态、版本、当班收入、待核差异、草稿/冲突角标）。
- 右侧按班次查看：油枪读数、现金、电子支付×回执匹配、站点待核回执、差异、冲正链、原始确认依据。
- 顶部可**模拟断网/恢复**、同步**晚到回执**、模拟银行新到回执，并可**新开窗口**做并发冲突演示。

### 推荐演示路径

1. 打开「早班（开放中）」：看到两笔电子已匹配、一笔银联无回执在待核；站点池有一笔无人认领回执（差异保留、不计收入）。
2. 点「模拟断网」→ 修改现金/泵码后「离线留草稿」→ 草稿进待发草稿箱；点「模拟恢复」→ 自动合并生效、版本 +1。
3. 「晚班（已确认）」：确认依据已冻结。点顶部「同步晚到回执」→ 自动追加晚到冲正，收入补上、待核差异归零、原快照不变。
4. 在晚班支付行点「登记跨班退款」，或用「泵码更新」表单追加冲正，查看冲正链与口径重算。
5. 顶部「↗ 新开窗口」，两个窗口同时编辑同一开放班并先后保存：后保存的一方得到冲突草稿，不覆盖先生效结果。

## 目录

- `src/domain/types.ts` 领域模型与操作类型（乐观锁、冲正、快照）
- `src/domain/recon.ts` 核销纯函数（匹配、待核、冲正叠加口径）
- `src/domain/server.ts` 服务端归约（操作应用、幂等、版本冲突、晚到回执路由）
- `src/domain/seed.ts` 演示数据
- `src/stores/recon.ts` Pinia：本地服务端、离线 outbox、多窗口同步、冲突草稿
- `src/components/*` 油枪表、支付/回执表、冲正链、冲突面板、班次详情
- `tests/*` 领域规则与离线/并发/续处理集成测试
